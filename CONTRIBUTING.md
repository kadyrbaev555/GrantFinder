# Как внести вклад в GrantFinder

Спасибо, что хотите помочь проекту. Ниже описано, как у нас устроена работа, чтобы ваш вклад было легко проверить и принять.

## Чем можно помочь

- **Предложить программу.** Знаете стипендию или грант, которых нет в каталоге? Откройте issue по шаблону «Новая программа».
- **Сообщить об ошибке.** Неверный срок, битая ссылка, что-то не работает в интерфейсе — откройте issue по шаблону «Ошибка».
- **Исправить код.** Backend на Go, frontend на React. Возьмите открытый issue или сначала опишите свою идею в новом.
- **Улучшить документацию.** Опечатки, неясные места, недостающие инструкции — это тоже полноценный вклад.

Перед крупными изменениями откройте issue и обсудите идею. Так вы не потратите время на то, что мы не сможем принять.

## Порядок работы

Мы работаем через ветки и pull request'ы. Прямые коммиты в `main` не делаем.

1. Если у вас нет прав на запись в репозиторий, сделайте fork. Участники команды работают в основном репозитории.
2. Обновите локальный `main` и создайте от него ветку:

   ```bash
   git checkout main
   git pull
   git checkout -b docs/fix-readme-typo
   ```

3. Внесите изменения и сделайте один или несколько коммитов.
4. Отправьте ветку на GitHub: `git push -u origin docs/fix-readme-typo`.
5. Откройте pull request в `main` и заполните шаблон: что сделано, зачем, как проверить.
6. Дождитесь ревью. Нужен хотя бы один approve от другого участника и зелёная проверка Secret Leak Check.
7. После слияния ветку можно удалить.

### Названия веток

Префикс показывает тип задачи, дальше — короткое описание через дефис:

| Префикс | Когда использовать | Пример |
| --- | --- | --- |
| `feat/` | новая функция | `feat/deadline-filter` |
| `fix/` | исправление ошибки | `fix/empty-search-results` |
| `docs/` | документация | `docs/api-examples` |
| `data/` | добавление или правка программ в каталоге | `data/add-gks-2027` |
| `ci/` | GitHub Actions, Dependabot | `ci/add-go-tests` |

### Сообщения коммитов

Пишем на английском в формате [Conventional Commits](https://www.conventionalcommits.org/): `тип: что сделано`.

```text
feat: add deadline filter to the catalog
fix: show "Срок не указан" when deadline is null
docs: describe how to add a new scholarship
data: add Stipendium Hungaricum 2027 call
```

Один коммит — одно логическое изменение. «fix», «update», «last files» без пояснений не пишем.

## Как добавить программу в каталог

Данные — основа проекта, поэтому к ним требования строже, чем к коду.

1. **Источник только официальный:** сайт организатора, посольства, министерства или вуза. Агрегаторы, Telegram-каналы и блоги не подходят даже как подтверждение.
2. **Описание своими словами.** Не копируйте абзацы с сайтов программ — коротко перескажите главное.
3. **Заполните все поля:**

   | Поле | Что писать |
   | --- | --- |
   | `title` | официальное название программы |
   | `organizer` | кто проводит и финансирует |
   | `country` | страна обучения (`Международная`, если стран несколько) |
   | `education_level` | уровни через запятую: `Foundation`, `Бакалавриат`, `Магистратура`, `Докторантура`, `Исследования`, `Стажировки` |
   | `funding_type` | `Полное финансирование`, `Грант`, `Государственная стипендия` или `Зависит от программы` |
   | `deadline` | дата в формате `YYYY-MM-DD` или `null`, если единого срока нет или он не подтверждён |
   | `description` | 1–3 предложения о программе |
   | `requirements` | основные требования, каждое с новой строки |
   | `funding_details` | что именно покрывается |
   | `official_url` | прямая ссылка на страницу программы |

4. **Добавьте запись в два места:**
   - в `docs/scholarships.json` — это открытый список данных проекта;
   - в новую миграцию `backend/migrations/0000N_<короткое_имя>.sql` со следующим номером. В секции `-- +goose Up` — `INSERT`, в секции `-- +goose Down` — `DELETE` этой же записи по `organizer` и `title`. Пример — `00002_fill_in_the_catalog.sql`.
5. **Проверьте локально:** `make backend`, затем `docker compose run --rm migrate /app/migrate status` и откройте программу в каталоге.
6. **В описании PR** укажите ссылку на источник и дату проверки.

Если срок подачи прошёл, не удаляйте программу. Обновите `deadline` и добавьте в `description` пометку о том, что приём закрыт.

## Перед отправкой PR

- [ ] Ветка создана от свежего `main`
- [ ] Проект запускается через `make up`, страница каталога открывается
- [ ] Нет файлов `.env`, паролей, токенов и личных данных
- [ ] Новые данные взяты с официальных сайтов
- [ ] README или docs обновлены, если поменялось поведение
- [ ] В PR указан связанный issue (`Closes #12`)
